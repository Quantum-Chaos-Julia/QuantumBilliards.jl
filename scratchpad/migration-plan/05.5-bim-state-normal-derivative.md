# Step 5.5 — `BIMEigenstate` stores `∂ₙψ` for free; generic `solve_state` for every `SweepBIMSolver`

## Status

**Implemented** (this step was executed immediately upon being added to the
plan, not left as a work order — see "Definition of done" below for what was
actually verified).

## Goal

Before this step, every one of `boundary_function`/`momentum_function`/
`wavefunction`/`husimi_function` for `BIMEigenstate` (all scoped to
`DoubleLayerPotentialSolver` only) independently called
`_dlp_boundary_function`, which:

1. re-ran `evaluate_points` (even though `compute_eigenstate` already had `pts`),
2. assembled a *second* dense Fredholm matrix (`_dlp_adjoint_fredholm_matrix`,
   an `O(n^2)` elementwise reweighting of the *already-assembled* primal
   matrix), and
3. ran a *second* `KrylovKit.svdsolve`,

every single time any of those four functions was called — up to 4x redundant
work versus what `compute_eigenstate` already computed, and *fully*
redundant with each other if a caller used more than one of them on the same
state.

The key realization (confirmed below, not just asserted): `∂ₙψ` is
recoverable **for free** from the same `KrylovKit.svdsolve(A, 1, :SR)` call
`solve_vect` already performs, because primal and adjoint problems are
related by transpose. `BIMEigenstate` now stores `u = ∂ₙψ`, `pts` and
`bnd_norm` directly, computed once by a new generic `solve_state` at
`compute_eigenstate` time; all four downstream functions are now plain field
reads, **generalized to any `SweepBIMSolver`** (not just
`DoubleLayerPotentialSolver`), since none of the new machinery is
DLP-kernel-specific.

## The math (why this is exact, not a heuristic)

`solve`/`solve_vect`/`solve_state` all solve for the smallest singular
triplet of the primal Fredholm matrix `A(k)` via `KrylovKit.svdsolve`, i.e.
`A = UΣV*` (standard SVD, `*` = conjugate transpose): `A v_j = σ_j u_j`,
`A^* u_j = σ_j v_j`. `solve_vect` already returns `v_L` (the right singular
vector, `rvecs[1]`) as the primal density; it previously discarded `u_L`
(`lvecs[1]`, the left singular vector) entirely.

The physical `∂ₙψ` is instead the (near-)null right singular vector of the
*weighted-transpose* adjoint operator `A_adj(k) = W⁻¹A(k)ᵀW` (`W = diag(ds)`,
**bilinear** transpose, not conjugate transpose — this is what
`_dlp_adjoint_fredholm_matrix` used to assemble explicitly). Transposing the
SVD: `Aᵀ = V̄ΣŪ*`, i.e. `Aᵀ`'s right singular vectors are the *conjugates* of
`A`'s left singular vectors: conjugating `A^*u_j = σ_j v_j` gives
`Aᵀ ū_j = σ_j v̄_j`. Consequently `y = W⁻¹ū_L` satisfies
`A_adj(k) y = W⁻¹Aᵀ(Wy) = W⁻¹Aᵀū_L = W⁻¹·σ_L·v̄_L`, which is exactly zero
whenever `Aᵀū_L` is exactly zero (a true eigenvalue), and is an
approximation of the same quality elsewhere as the primal tension already
is. So `_bim_normal_derivative(solver, pts, lvec) = conj.(lvec) ./ pts.ds[idx]`
recovers (up to the final Rellich rescaling, which removes any residual
scale ambiguity) the *same* physical `∂ₙψ` the old two-matrix, two-solve path
computed — **verified numerically** (see Definition of done) to agree with
the old adjoint-matrix path to machine precision (smooth/symmetric cases) or
~1e-6 relative (Kress-graded corners, where the two paths' Krylov iterations
converge to slightly different numerical noise floors), up to the single
unavoidable global complex phase every singular vector carries.

This reciprocity is a property of *any* Nyström-discretized boundary-integral
operator built from a diagonal quadrature weight `W = diag(ds)` — not
specific to the double-layer kernel — which is why `_bim_normal_derivative`,
`symmetrize_layer_density` and `solve_state` are defined once, generically,
on `AbsBIMSolver`/`SweepBIMSolver`, rather than per concrete solver.

## On "is the sampling suitable for reconstruction" (the caveat in the request)

Confirmed **not an issue**: `pts` stored in `BIMEigenstate` is *exactly* the
same `BoundaryPoints` `evaluate_points(solver, billiard, k)` produced for the
eigenvalue solve at the (already-located) wavenumber `k` — this is the exact
same discretization `_dlp_boundary_function`'s old re-evaluation would have
produced anyway (`evaluate_points` is a pure function of `(solver, billiard,
k)`), so reusing it is a pure optimization with zero accuracy change. The
existing `_bim_boundary_uniformly_spaced` warning in `husimi_function`
(triggered by `GlobalCornerGrading`'s intentional corner clustering) already
covers the one genuine grading-dependent suitability concern and needed no
changes.

## Numerical verification performed

1. Full existing regression suite (`test/solvertests.jl`, all Decomposition/
   Vergini-Saraceno/DLP testsets including the Stadium symmetry-reduced
   matrix-consistency test) passes unchanged — `state.ten`/`state.dim`/
   `length(state.vec)` are bit-for-bit the same computation as before (same
   single `KrylovKit.svdsolve` call, just also capturing `lvecs`).
2. Manual cross-check script (not a committed test file — flagged to the
   Julia Test Writer subagent below): re-implemented the *old*
   `_dlp_adjoint_fredholm_matrix`/`_dlp_boundary_function` path standalone
   and compared its `u` against the new `state.u` for:
   * Circle, `SmoothPeriodicGrading`, no symmetry — phase-aligned relative
     difference `5.4e-16` (machine precision).
   * Triangle, `GlobalCornerGrading`, no symmetry — `2.4e-6` (two
     independent Krylov solves on differently-conditioned matrices, still
     far below the tension scale).
   * Stadium, `YAxisReflection` symmetry-reduced — `7.3e-16`.
3. Confirmed `boundary_function`/`momentum_function`/`husimi_function`/
   `wavefunction` all execute correctly (finite, non-all-`NaN` output; correct
   `GlobalCornerGrading` non-uniform-spacing warning still fires) for all
   three fixtures above.
4. Corrected an inaccurate docstring claim in the initial draft: `bnd_norm`
   (the raw pre-rescaling Rellich value) is *not* expected to be close to
   `1` — only `_rellich` evaluated on the **already-rescaled** `u` is
   (trivially, by construction of the rescaling itself); `bnd_norm`'s own
   numeric value is an arbitrary artifact of the Krylov solve's own vector
   normalization and differs from what the old two-solve path happened to
   produce (verified: old norms were `2.7e-3`/`1.6e-4`/`1.5e-3`, new ones are
   `2.75`/`0.126`/`1.10` for the three fixtures above — different scales,
   *same* final `u` after rescaling, exactly as the math above predicts).
