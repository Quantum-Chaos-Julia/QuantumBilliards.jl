Tutorial

This section will guide you through getting started with QuantumBilliards.jl.

Installation

using Pkg
Pkg.add(url="https://github.com/Quantum-Chaos-Julia/QuantumBilliards.jl")

Core components

A computation combines a billiard from BilliardGeometry.jl, a solver and, for basis solvers, a basis. Boundary-integral solvers such as BeynSolver and CORKSolver wrap a kernel (DoubleLayerPotentialSolver, CombinedFieldIntegralEquationSolver or CompositeBIMSolver); basis solvers such as VerginiSaracenoSolver use a basis such as FourierBessel, CornerAdaptedFourierBessel or RealPlaneWaves. compute_spectrum returns a SpectralData from which wavefunction, boundary_function and husimi_function reconstruct the states.

using QuantumBilliards, BilliardGeometry
billiard = C3Billiard(0.2)
kernel = DoubleLayerPotentialSolver(8.0, billiard)
solver = BeynSolver(kernel; nlevels = 10)
k1, k2 = k_range_for_states(billiard, 250, 257)
spectrum = compute_spectrum(solver, billiard, k1, k2)

The solver structs are immutable. with_params returns a copy with some fields replaced, for example with_params(solver; nq = 60), and displaying a solver at the REPL (or log_solver) lists its parameters.

Planning a computation

plan_computation describes a compute_spectrum run without solving: the window layout, the expected number of states per window (Weyl law), the basis or boundary dimensions, an upper-bound memory estimate and notes about parameter adjustments. The resulting ComputationPlan stores every input of the run, so compute_spectrum accepts it directly.

plan = plan_computation(solver, billiard, k1, k2)    # or (solver, billiard, N1, N2) with state indices
plan                                                 # prints windows, dimensions and memory
spectrum = compute_spectrum(plan; show_progress = false)

For VerginiSaracenoSolver pass the basis and the window half-width, plan_computation(solver, basis, billiard, k1, k2, dk); for ExpandedBIMSolver the half-width is the keyword dk. compute_spectrum checks the same estimate before the sweep and throws if it exceeds max_memory (by default default_memory_limit, 90% of the physical RAM); pass max_memory = Inf to disable the check. estimate_memory returns the estimate alone.

Billiards with holes and symmetry

A billiard with holes has the symmetry group G' of the elements of its registered group G that map every hole onto itself (BilliardGeometry.get_symmetry_group). Holes that carry their own symmetry are built from one fundamental piece with SymmetricHole; copies of a hole placed by the symmetry of the billiard are built with SymmetrizedHoles. The origin-centered SinaiBilliard (D₄), AnnularBilliard (mirror y → -y) and a single concentric SquareWithinSquareBilliard (D₄) are built this way; a nonzero center gives the unreduced billiard with an empty registry.

A composite boundary-integral solver acts on the reduced billiard through the irreducible representations of G'. The one-dimensional irreps are selected with symmetry_sector; symmetry = nothing solves the whole billiard.

b = SinaiBilliard(1.0, 0.3)
sector = symmetry_sector(b, DiagonalReflection => 1, YAxisReflection => -1)

A symmetry that a hole breaks is rejected with an error that names G' and the first offending hole; use a subgroup of G' or symmetry = nothing.

For a dihedral group D_d the two-dimensional irreps E_k (1 ≤ k < d/2) are selected with the irrep2d keyword. E_k restricts to the cyclic sectors s = k and s = d-k, so the solve runs in the cyclic sector s = k, which contains every E_k level once; each level is twofold degenerate in the full problem (symmetry_degeneracy(sector) == 2). symmetry_irreps(b).irreps_2d lists the valid k, and symmetry_partner(f, b) gives the degenerate partner f∘σ of a state.

b = SinaiBilliard(1.0, 0.3)               # D₄: E₁ is the only 2D irrep
sector = symmetry_sector(b; irrep2d = 1)

Profiling a spectrum computation

The accelerated solvers (VerginiSaracenoSolver, BeynSolver, ExpandedBIMSolver, CORKSolver) are instrumented with @timeit_debug (TimerOutputs) and @debug (Logging). Both are no-ops by default.

using TimerOutputs, QuantumBilliards
TimerOutputs.enable_debug_timings(QuantumBilliards)   # before the first call; triggers recompilation
reset_timer!()
ENV["JULIA_DEBUG"] = "QuantumBilliards"               # optional: sizes, ranks, memory markers
data = compute_spectrum(solver, billiard, k1, k2; show_progress = false)
print_timer(; allocations = true)

The timer tree is rooted at compute_spectrum_vs, compute_spectrum_beyn, compute_spectrum_ebim or compute_spectrum_cork, with three stage children, preparation (boundary points, caches, polynomial/degree tuning), solution (window solves) and postprocessing (state construction, merging, finalization), and the performance-critical steps (matrix assembly, factorizations, eigen/SVD/Krylov) below them. Notes:

  • Allocation columns count Julia allocations only; BLAS/LAPACK workspace and peak memory are not included. @debug lines report live_GiB and maxrss_GiB at sweep boundaries, and matrix construction messages report each matrix size and memory in GiB.
  • Each @debug call site prints only once per logger (maxlog=1), so repeated windows do not flood the output.
  • The default timer is not thread-safe. Timers are placed around whole loops, never inside threaded loop bodies.
